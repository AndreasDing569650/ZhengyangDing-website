Matching Parents and Children with SQL in Python

SQL Tutorial
Intergenerational income
Published

October 22, 2026

Introduction

Inter-generational income mobility studies the extent to which economic outcomes are associated across generations. To estimate this relationship, we first need to identify which children belong to which parents and then construct comparable measures of family income for each generation.

This project uses data from the Panel Study of Income Dynamics (PSID) and implements the parent-child matching procedure in Python with SQLite. The analysis has three main steps. First, the raw individual-level PSID data are reshaped into a longitudinal person-year dataset. Second, biological mothers and fathers are identified using the PSID parent-identification file and matched to their children with SQL. Finally, parent and child family income are constructed for both 2022 and the 2020–2022 period and used to estimate intergenerational income elasticity (IGE).

The main purpose of the SQL stage is to connect parent identifiers with longitudinal individual records, impose the required family restrictions, and aggregate income across parents and years.

Data and Matching Problem

The PSID provides information on individuals, families, and family relationships over time. The individual data used in this project contain observations for 2020 and 2022. Each individual is identified using a permanent person identifier constructed from the PSID family and person identifiers.

After processing the raw data, the longitudinal dataset contains variables such as:

  • person_id: permanent individual identifier
  • family_id: family identifier in the corresponding survey year
  • family_income: total income of the individual’s family unit
  • year: survey year
  • age: individual’s age

The parent-identification file provides the identifiers needed to connect a child to their biological mother and father. The relevant variables are PID2, PID3 for the child, PID4, PID5 for the biological mother, and PID23, PID24 for the biological father.

The first step is to convert these identifier components into the same person_id format used in the longitudinal individual data. This makes it possible to connect the parent-identification records directly to the individual-level observations.

The analysis constructs two income measures. The first uses family income observed in 2022. The second uses the average of family income observed in 2020 and 2022. In the final sample, both children and parents are restricted to ages 25–64 in 2022, and parent-child pairs are required to live in different families in the relevant year.

Loading the Data into SQLite

After the data-processing step, the two cleaned files are loaded into an SQLite database. The individual-level data are stored in an individual table, while the parent-identification data are stored in a separate parent_identification table.

import pandas as pd
import sqlite3
from pathlib import Path

project_root = Path(r"C:\Users\lenovo\PycharmProjects\6400_blog_6")
cleaned_dir = project_root / "data" / "cleaned_data"

individual_data = pd.read_csv(
    cleaned_dir / "individual_long.csv"
)

parent_identification = pd.read_csv(
    cleaned_dir / "parent_identification.csv"
)

conn = sqlite3.connect(
    cleaned_dir / "psid_matching.db"
)

individual_data[
    ["person_id", "family_id", "family_income", "year", "age"]
].to_sql(
    "individual",
    conn,
    if_exists="replace",
    index=False
)

parent_identification[
    ["child_id", "mother_id", "father_id"]
].to_sql(
    "parent_identification",
    conn,
    if_exists="replace",
    index=False
)

The two tables play different roles. The parent_identification table describes the family relationship, while the individual table contains the longitudinal information needed to measure income, family membership, and age.

Indexes are then created on the identifiers used repeatedly in the SQL joins.

cursor = conn.cursor()

cursor.execute("""
CREATE INDEX IF NOT EXISTS idx_individual_person_year
ON individual(person_id, year)
""")

cursor.execute("""
CREATE INDEX IF NOT EXISTS idx_parent_child
ON parent_identification(child_id)
""")

conn.commit()

Constructing the Parent-Child Relationship

The parent-identification file contains separate identifiers for the biological mother and father. To make the subsequent SQL operations more straightforward, these two relationships are converted into a single parent-child bridge table.

CREATE TABLE parent_child AS

SELECT
    child_id,
    mother_id AS parent_id,
    'mother' AS parent_type
FROM parent_identification
WHERE mother_id IS NOT NULL

UNION ALL

SELECT
    child_id,
    father_id AS parent_id,
    'father' AS parent_type
FROM parent_identification
WHERE father_id IS NOT NULL;

The resulting table contains one row for each child-parent relationship. A child with both a biological mother and father can therefore appear twice, once for each parent.

This bridge table separates the relationship information from the longitudinal information. The parent_child table tells us who is connected to whom, while the individual table tells us what each person’s family income, family membership, and age were in a given year.

Matching Parents and Children in 2022

We first construct the single-year income measure using observations from 2022.

The SQL query joins the parent-child bridge table to the individual data twice: once to obtain the parent’s 2022 observation and once to obtain the child’s 2022 observation.

SELECT
    pc.child_id,

    AVG(parent.family_income)
        AS parent_income_2022,

    child.family_income
        AS child_income_2022,

    child.age
        AS child_age_2022,

    AVG(parent.age)
        AS parent_age_2022

FROM parent_child AS pc

JOIN individual AS parent
    ON pc.parent_id = parent.person_id
    AND parent.year = 2022

JOIN individual AS child
    ON pc.child_id = child.person_id
    AND child.year = 2022

WHERE parent.family_id != child.family_id

GROUP BY
    pc.child_id,
    child.family_income,
    child.age;

The first JOIN retrieves the parent’s 2022 observation, while the second retrieves the child’s observation from the same longitudinal table. The condition

parent.family_id != child.family_id

requires the parent and child to belong to different families in 2022.

The query then uses GROUP BY to organize the matched observations by child. Since a child can be linked to both a biological mother and father, AVG(parent.family_income) combines the available parent income observations into a single parent-income measure. The same aggregation is used for parent age.

The resulting variables are therefore parent_income_2022, child_income_2022, child_age_2022, and parent_age_2022.

Constructing the 2020–2022 Income Measure

The second income measure uses information from both 2020 and 2022. Instead of relying on a single year’s income, we construct an average income measure across the two survey years.

The SQL query retrieves observations for both generations in both years:

SELECT
    pc.child_id,

    AVG(parent_2020.family_income)
        AS parent_income_2020,

    AVG(parent_2022.family_income)
        AS parent_income_2022,

    child_2020.family_income
        AS child_income_2020,

    child_2022.family_income
        AS child_income_2022,

    child_2022.age
        AS child_age_2022,

    AVG(parent_2022.age)
        AS parent_age_2022

FROM parent_child AS pc

JOIN individual AS parent_2020
    ON pc.parent_id = parent_2020.person_id
    AND parent_2020.year = 2020

JOIN individual AS parent_2022
    ON pc.parent_id = parent_2022.person_id
    AND parent_2022.year = 2022

JOIN individual AS child_2020
    ON pc.child_id = child_2020.person_id
    AND child_2020.year = 2020

JOIN individual AS child_2022
    ON pc.child_id = child_2022.person_id
    AND child_2022.year = 2022

WHERE
    parent_2020.family_id != child_2020.family_id
    AND parent_2022.family_id != child_2022.family_id

GROUP BY
    pc.child_id,
    child_2020.family_income,
    child_2022.family_income,
    child_2022.age;

Here, the parent and child observations are matched across both years. The family-separation condition is also imposed separately in 2020 and 2022, so the parent and child must belong to different families in both years.

After the SQL query returns the four income variables, Python constructs the two-year averages:

parent_income_avg = (
    parent_income_2020 + parent_income_2022
) / 2

child_income_avg = (
    child_income_2020 + child_income_2022
) / 2

The single-year and multi-year results are then merged using the child identifier:

matched_data = single_year.merge(
    multi_year,
    on="child_id",
    how="inner"
)

This produces a dataset in which the same matched children have both the 2022 income measures and the 2020–2022 average income measures.

Applying the Sample Restrictions

Before estimating the regressions, the analysis removes observations with non-positive income. This is necessary because the regression uses logarithmic income.

matched_data = matched_data[
    (matched_data["parent_income_2022"] > 0) &
    (matched_data["child_income_2022"] > 0) &
    (matched_data["parent_income_avg"] > 0) &
    (matched_data["child_income_avg"] > 0)
]

The working-age restriction is then applied using age in 2022:

matched_data = matched_data[
    matched_data["child_age_2022"].between(25, 64) &
    matched_data["parent_age_2022"].between(25, 64)
]

Thus, the final estimation sample contains parent-child pairs for which both generations are between 25 and 64 in 2022 and all income measures used in the regressions are positive.

Estimating Intergenerational Income Elasticity

The final step is to estimate the relationship between parent and child family income.

The analysis uses a log-log specification:

[ (Y_i^{child}) = + (Y_i^{parent}) + _i. ]

The coefficient () is the intergenerational income elasticity (IGE). It measures how strongly differences in parent income are associated with differences in child income.

For the 2022 single-year measure, the analysis takes the natural logarithm of parent and child income and estimates the relationship using OLS:

single_year["log_parent_income"] = np.log(
    single_year["parent_income_2022"]
)

single_year["log_child_income"] = np.log(
    single_year["child_income_2022"]
)

X = sm.add_constant(
    single_year["log_parent_income"]
)

model_single = sm.OLS(
    single_year["log_child_income"],
    X
).fit()

The same procedure is applied to the 2020–2022 average income:

multi_year["log_parent_income"] = np.log(
    multi_year["parent_income_avg"]
)

multi_year["log_child_income"] = np.log(
    multi_year["child_income_avg"]
)

X = sm.add_constant(
    multi_year["log_parent_income"]
)

model_multi = sm.OLS(
    multi_year["log_child_income"],
    X
).fit()

The analysis extracts the estimated IGE coefficient, standard error, p-value, sample size, and (R^2) from each model and saves them to the regression results file.

Results

The two specifications produce the following results:

Income measure Observations IGE Standard Error (R^2)
2022 single-year income 1,635 0.245 0.023 0.065
2020–2022 average income 1,635 0.280 0.022 0.092

For the 2022 single-year measure, the estimated IGE is 0.245 with a standard error of 0.023. For the 2020–2022 average measure, the estimated IGE increases to 0.280, with a standard error of 0.022.

The results indicate a positive relationship between parent and child family income in both specifications. The higher IGE obtained using the two-year average also suggests that the estimated intergenerational income relationship is sensitive to how income is measured over time.

Life-Cycle Bias

Income is not necessarily a stable measure of an individual’s long-run economic position. A person’s income in any particular year can contain temporary fluctuations. Using only one year’s income may therefore introduce measurement noise into the intergenerational income relationship.

The single-year specification uses family income observed in 2022:

[ (Y_i^{child,2022}) = + (Y_i^{parent,2022}) + _i. ]

The alternative specification uses average family income over 2020 and 2022:

[ ( ) = + ( ) + _i. ]

Averaging income across multiple years can reduce the influence of temporary income fluctuations and provide a measure that is closer to an individual’s longer-run economic position.

In our results, the estimated IGE increases from 0.245 using 2022 income to 0.280 using the 2020–2022 average. The (R^2) also increases from 0.065 to 0.092. This comparison illustrates how the estimated degree of intergenerational persistence can change when income is measured over a longer period.

The Takeaway

This project demonstrates how SQL can be used to solve a longitudinal parent-child matching problem using PSID data.

The main steps are:

  1. Reshape the PSID data into a person-year structure so individuals can be tracked across 2020 and 2022.
  2. Construct a parent-child bridge table from the biological parent identifiers.
  3. Use SQL JOIN operations to connect parents and children to their individual-level observations.
  4. Use GROUP BY and aggregation to construct parent-level income and age measures.
  5. Construct both single-year and multi-year income measures to examine the sensitivity of IGE to income measurement.
  6. Estimate log-log OLS regressions to obtain the intergenerational income elasticity.

The main lesson is that SQL provides a clear way to organize relationship matching, longitudinal joins, and aggregation when working with complex panel data. In this project, the parent-child bridge table connects the family relationship information to the longitudinal PSID records, while the SQL joins and aggregation operations transform those matched records into the income measures required for the final IGE analysis.
